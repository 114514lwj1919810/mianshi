# GD32 / Unity V3.2 同步改动

## 权威边界

GD32 管理设置、余额、真实投退币、返奖账目、有限球池和比赛结果。
Unity 只显示状态和播放指定胜者动画，不抽取胜者、不本地记账。
串口保持 USART2（通常称串口3），PB10/PB11，115200，8N1。
必须成对更新 GD32 固件和 V3.2 APK。GD32 不接受旧 3.1 握手开启比赛。

## 计算及状态

下注、倍率、投币、实退币、已承诺奖励、球池或设置变化会标记重算。
预计算不消耗球、不推进随机数、不记奖。开始时再次计算并锁定下注、倍率、胜者和奖励。
有限球池以空、小、中、大、特大五类控制节奏，不给六个动物分配获胜权重。
控奖投入以每局按开始键后锁定的实际下注流水累计，包含中奖积分再次下注形成的流水；
仅投币但尚未下注的积分不进入返奖预算。预算只减已承诺奖励，不读取实退积分决定胜者。
真实投币枚数/积分与光眼确认的真实退币枚数/积分独立累计，只用于现金查账。
中奖在开始键锁定胜者时记一次已承诺奖励，之后结果显示、收分入余额和集中退币都不重复记奖。
当大球暂无可支付候选时保留大球欠账，后续有实际可支付的大结果时优先消化。
连续未奖达到随机3～5局期限时，在玩家当前下注确实存在合法小奖候选的前提下触发小奖；
任何真实奖励都会重置期限。小奖同样进入已承诺奖励，不能绕过总返奖账目。
已承诺奖励高于正常目标时进入亏空期，只按亏空降率后的新下注流水建立独立预算；
旧亏空不能直接透支未来全部流水，恢复到正常目标后自动清空亏空预算。
六套倍率逐局固定；随机模式从六套中选一套。狮子押注达到300/500时沿用32/40倍提升。
动物ID为：1狮子、2大象、3猩猩、4斑马、5长颈鹿、6骆驼，与Unity一致。

实际能返多少仍受玩家下注和显示倍率限制：所有动物都被下注时可能没有零奖结果；
只押高倍动物时也可能不存在小奖候选。算法不能凭空制造任意返奖金额。

流程：IDLE -> BETTING -> WAIT_RACE_OVER -> WAIT_RESULT_OVER -> WIN_WAIT_START
-> WIN_COLLECTING -> IDLE/BETTING。零奖跳过收分。设置和出币有独立状态。
RACE_OVER/RESULT_OVER必须匹配本局序号和局号；重复回报不重复派奖。
动画回报超时可继续结算，重连通过完整状态恢复，不能改写已锁定结果。

## EEPROM

AT24CS64 0x0000..0x1DFF 分十个768字节槽，存设置、钱包、累计账目、球池和当前事务。
记录有版本、长度、序号、CRC、最后提交标记。先保存并校验，后发布比赛或设置成功。
未完成写入不会覆盖上一个有效事务。旧V2设置0x1F00可迁移；不迁移不存在的旧账目。
新空白EEPROM写默认值。有损坏数据但没有有效记录时不擅自清账。
fault=1仍不上报；存储失败以storage=0显示并暂停新财务操作，自动重试。
收分保持每秒10分，以每秒一次事务落盘；运行时间每分钟检查点，掉电最多损失约一分钟计时。
真实机械出币和EEPROM写入之间仍有断电窗口，不能用纯软件承诺绝不漏计；
量产需掉电保持/出币器独立计数/供电保障，并进行实机断电测试。

## 协议

ASCII行，以CRLF结束，两端最大行长1024字节，超长整帧丢弃，不截断成有效命令。
常见报文已压缩，保留余量应对累计账目位数增长，不以256字节作为硬上限。
默认快照长度：设置161、账目47、完整状态131字节（不含CRLF）。
动画指令和ACK沿用原命令；握手版本变为3.2。

### 待机演示状态（2026-09-18）

GD32新增独立的瞬时待机状态 `OFF -> RACE -> RESULT -> RACE...`，不写入正式游戏状态，
也不调用正式开局、胜者控制、派奖、收分、投退币或账目接口。只有设备已握手、存储正常、
正式状态为IDLE且余额/下注/WIN/待退币全部为0时才会启动。演示胜者由GD32独立xorshift随机数产生，
不消耗有限球池，不增加正式局号、累计局数或承诺奖励。

GD32沿用Unity现有比赛画面报文，但追加 `demo=1`：

- `SHOW_RACE:...,bets=0|0|0|0|0|0,...,demo=1`
- `SHOW_RESULT:...,win_total=0,win_remaining=0,duration_ms=3000,demo=1`

Unity对演示局分别回报 `DEMO_RACE_OVER:seq=...,round=...` 和
`DEMO_RESULT_OVER:seq=...,round=...`，不会发送可能进入正式结算的 `RACE_OVER/RESULT_OVER`。
胜者结果实际显示3秒，收到结果完成回报后GD32立即生成下一演示局；回报丢失时由独立超时兜底。
投币、设置键或任何正式状态变化会立即退出待机；权威IDLE/BETTING报文可中断同局号的演示画面。
PC独立测试版也按相同报文和时序自动循环，用任意键退出演示并回到试玩下注页。

完整状态命令 `F` 字段映射：

|短字段|含义|
|---|---|
|s,p,r,c,t,i|序号、状态、局号、余额、总下注、选中ID|
|b,o|六路下注、六路倍率，使用竖线分隔|
|w,wt,wr,l|胜者、总赢分、待收赢分、上局赢分|
|rs,es,cs,ca|比赛序号、结果序号、收分序号、收分活动标志|
|pp,f,pt,pd|待退枚数、故障码、计划退币数、已退枚数|
|rt,et,ct|比赛/结果/收分剩余毫秒|

账目 `A:v=1,d=...` 固定20项，以竖线分隔：
投币枚数、退币枚数、投币积分、退币积分、已承诺返奖、累计游戏流水、局数、大结果数、
彩票数、运行秒数、报账次数、报账基准投币数、报账基准退币数、基准投币积分、
基准退币积分、亏空期预算(积分×万分比)、大球欠账、余额、待收赢分、待退枚数。
Unity仍兼容原长字段FULL_STATE/ACCOUNT_SNAPSHOT，GD32发送短格式。

设置读取 `SETTINGS_GET` -> `SETTINGS_SNAPSHOT:schema=1,rev=N,storage=1,values=...`。
保存 `SETTINGS_APPLY:req=N,base_rev=N,values=...`，必须携带完整37项。
`CONTROL_RESULT:req=N,status=OK,rev=N` 后仍须以设备新快照更新页面。
版本不一致返回CONFLICT；重复请求不重复保存。密码快照始终为0，保存0代表不修改密码。
`SERVICE_ENTER` / `SERVICE_EXIT` 带req；`SERVICE_AUTH`带req和password。
`ACCOUNT_REPORT` / `ACCOUNT_CLEAR`带req和base_rev（报账次数），需要验证系统密码。
报账/清分只移动报账基准，不删除累计返奖账目或球池。
设备按键转发 `MENU_KEY:key=UP|DOWN|LEFT|RIGHT|CONFIRM|BACK`。
`SERVICE_STATE:open=0|1` 同步设置页开关。管理请求独立于动画序号。

## 37项设置索引

0比赛毫秒，1结果毫秒，2投币积分，3最小下注，4单局总下注上限，5退币积分/币，
6目标返奖率(万分比)，7..12旧基础倍率保留只读，13主机音量(0..16)，14机器号，
15串口调试标志，16球池档位(1..5)，17小奖节奏强度(0关闭；1..10最多5局；11..20为4～5局；21..30为3～5局)，18倍率方案(0随机/1..6固定)，
19狮子下注上限，20其他动物下注上限，21彩票币数，22主/分机模式，23分机号，
24分机音量，25分机器类型，26分机器来源，27主机器类型，28主机器来源，
29运行分钟设置，30公式编码，31系统密码，32单局奖励上限，33亏空降率(万分比)，
34投币输入索引，35出币光眼索引，36出币电机输出索引。
输入输出索引从0开始，Unity显示IN1/OUT1从1开始；35/36均为255表示禁用出币。

现有设置页全部纳入存储/回读，新增返奖与硬件页。音量快照控制Unity AudioListener。
投退币类型作用于计数电平；更换币值/端口须无余额、无下注、无待收奖和待退币。
默认投币IN3。真实出币光眼/电机引脚尚未确认，因此默认禁用，不再用第二次按键伪造退币成功。

待确认定义的设置仅存储同步，不虚构硬件功能：
- 分机模式/分机号/来源尚未接入主从总线或娱乐麻将接口。
- 彩票币数已同步，但无出票硬件输入，彩票累计暂为0。
- 公式编码未参与计算，运行分钟设置未作为到时停机授权；实际运行秒数另外累计。
- 串口调试标志保留，诊断命令目前可用，未作为权限开关。
