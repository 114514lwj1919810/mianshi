# 10210007 预算防超发修补与测试

## 已确认与尚未确认

现场报告：亏空期间E池初始为0，新增5押分，老虎机实际入账3+3+3+5=14，C9也增加14。
在当前源码及Keil ARM固件的模拟环境中，按95%-15%=80%逐次押1分，未复现此超发；5次只发一次3币，余1币。
这不能否定现场问题，也不能据此宣布现场根因已经完全查清。

确认的代码缺陷：lottery.c将奖型枚举累加。COIN_5的枚举为3，重复提交会变为6（COIN_10），而非正确的独立奖励。
此次修复此缺陷，并强化预算到实际Game加奖之间的一次性许可。重复提交是可注入复现的风险，但尚未证明现场是由该条件触发。

## 修改范围

- E池保存本负账段开始押分、累计押分、累计按比例补入、累计小奖扣款。
- 余额由累计补入减扣款计算；补入不超过该段实际押分，扣款不得超过补入。
- 独立押分基准去重：重复OnStake、反复抽奖、旧last_stake倒退不会重复补池。
- 选出3/5/10后先扣池并成功保存，才签发一次性许可；Game成功入账后消耗许可。
- 队列忙时保留许可重试；伪造、错金额或重复领取拒绝入账，不退回虚假预算。
- 同一轮动画结果只能提交一次；奖型只赋值、不相加。
- 不修改P3/P15比例，不加保底，不增加亏空额外奖；自然连线与D池送灯规则保持。
- EEPROM算法记录V15仍128字节、原地址不变。旧V14无E收支证据，加载时只重建E池为0；正常升级仍按现有升级清零规则执行。

## 查账：原C1～C50不移位

| 页面 | 含义 | 读法 |
| --- | --- | --- |
| C48 | 固件版本 | 10210007 |
| C42 | 算法记录版本 | 15 |
| C51 | 最近开奖前可用预算 | 单位0.01币；320表示3.20币 |
| C52 | 最近一次开奖成功批准的直接币奖 | 0、3、5、10；不是重复可领取金额 |
| C53 | 当前负账段累计押分 | 不是全机C3 |
| C54 | 当前负账段累计补入E池 | 单位0.01币；400表示4币 |
| C55 | 当前负账段累计已扣的小奖 | 单位币 |
| C56 | 本次开机拒绝异常币奖次数 | 正常为0；不显示故障码 |

C51/C52/C56为运行诊断，重新开机清零；C53～C55随E池保存，恢复非负账时归零。
C22仍只显示整数余额，因此0可能代表0～0.99币，但不足3币绝不能据此签发3币奖。
正账C21=A-B为正不代表C22必然为正：普通预算=max(A×P3%-B-D,0)。
