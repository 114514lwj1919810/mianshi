# 元气小丑 固件10200001变更说明

当前主工程以收到的 `joker-v1_20261020` 为基线，整机版本为 **10210007**，算法记录为 V15。最新修补和C51～C56见《10210007_预算防超发修补与测试.md》。

## 本次修改

- C48显示版本 `1021 / 0007`，编码为“月日四位＋发布编号四位”，例如10200001、10200002、10210007。
- 版本常量位于 `Service/Inc/game.h` 的 `GAME_FIRMWARE_VERSION`。这个显示版本与安全升级包的递增release是两种独立编号，不能用10200001替换Bootloader的release。
- P15亏空返奖率降幅范围0～100，默认15；亏空有效比例为max(P3－P15，0)。例如P3=95、P15=15时，每成功押1币立即向E池增加0.8币；C22只显示整数部分，累计到3/5/10币才可能开出相应小奖，开奖后扣池。C3－C4转为非负时E池清零并回到普通预算。押分账本与E池在落币电机结束后按顺序保存，不延迟C22的内存显示。
- PB0上方落币光眼改为下降沿中断即停游戏电机，每次启动仅接受第一个有效边沿；不再使用4ms低电平滤波或等待上升沿。其他光眼的滤波不变。硬件噪声若造成误触发，可能提前停机并导致E16，须上机验证。
- P9彩金默认基值由100改为20。出厂设置或按当前升级策略清空设置后生效；手动保存过的旧值若没有恢复默认，不会被悄悄覆盖。
- 新增P17：正账每累计押P17币，才从C22普通奖预算转1币入D池，默认30币，范围10～200币。亏空押分不累计；正账C22不足1币时先记待转额度，等预算充足再转，D池不会凭空增加。C23仍显示D池余额；不再按每次老虎机开奖自动存1币。
- P14为0循环或1即玩即吐时，出票键都优先结算左屏。P14=0先经中屏逐个转到右屏；P14=1按当前出奖方式正常下发。只有左、中屏都没有待发奖励时，再按出票才能兑换右屏余额。
- 正在中屏转右屏时，等待本批转完后再兑换；正在落币、抽奖未出结果或高连线结算中的安全互锁仍有效。
- 兑出使用P1所选的出币、出票、出币兼出票或出卡流程；出卡不足一张的余数仍留中屏。兑换右屏余额不会新增总押、总中奖、连线分、彩金分或彩金贡献。实体吐币只随出口光眼计数。
- 新增老虎机3币、5币、10币实际入奖分项。它们在奖励成功进入中屏/队列时记一次，循环转屏与最终兑现不重复记。数据位于EEPROM 0x1580、0x15A0两个32字节槽，含版本、序号和CRC，不移动原账目。

## 当前设置编号

P1出奖方式；P2每局押分；P3正账返奖率；P4彩票换算；P5预留难度；P6清账；P7恢复默认；P8双音量；**P9彩金基值默认20**；P10出卡比例；P11待机音效；P12彩金押分增长门槛；P13单机/联机与机台号；P14奖励下发方式；**P15亏空降幅0～100**；P16大奖池起抽门槛；**P17每押多少币存D池1币，默认30、范围10～200**。

## 与替换前主工程的差异

- 设置27页归并成16页，内部参数存储下标保持相关旧位置。
- 返奖算法V13改为收到的V14：正账预算由(A－B)×P3－D改为A×P3－B－D。
- 大奖池由“每押P27币存1币”改为“正账每次1/9抽奖存1币”；达到P16再按90/175、55/175、30/175抽取5/6/7连线，并检查可支付性。
- 普通币奖按预算依次选择10/5/3，收到版本中P5为预留，不控制开奖。
- 电机驱动、光眼驱动、8KB栈和基本游戏状态机沿用收到工程；本次另增加统一右屏兑换入口。

工程包含原机8KB栈；当前改动只增加几十字节静态账目和32字节存储记录，没有使用递归或大数组扩栈。
