# Joker GD32 安全 IAP v2 格式

## 目标

v2 将“每台机器一套完整固件”改为“固件只加密一次，每台机器一个小密钥信封”。一张 TF 卡可以升级产品表中所有 `active` 机器。

## TF 目录

```text
IAP\
├─ APP_A.ENC
├─ APP_B.ENC
├─ DEVICES.SEC
└─ UPDATE.SEC
```

新空板的一次性初始化卡还会多一个 `IDENTITY.SEC`。该名称符合 Bootloader 只读 FAT32 驱动的 8.3 文件名限制。

## 密钥层次

1. 每台机器在 Sector 11 保存独立随机 `Kdevice`。
2. 每次制包随机生成 256 位 `Kfirmware`。
3. App A/B 均用 `Kfirmware` 执行 AES-256-GCM，但使用不同 Nonce 和 AAD。
4. 每台 active 机器使用由 `Kdevice + UID + 143-xxx + 型号` 派生的 KEK，把同一个 `Kfirmware` 包成独立 AES-GCM 信封。
5. `UPDATE.SEC` 使用厂家 Ed25519 私钥签名。Bootloader 只包含公钥。

## DEVICES.SEC

文件头为 24 字节，记录数、型号、release 和单条长度都受 `UPDATE.SEC` 签名保护。

每条记录 76 字节：

| 字段 | 长度 | 含义 |
| --- | ---: | --- |
| lookup | 16 | 由本机 `Kdevice + release` 算出的匿名查找值 |
| nonce | 12 | 本信封 AES-GCM Nonce |
| wrapped_key | 32 | `Kfirmware` 密文 |
| tag | 16 | 本信封 GCM 认证标签 |

记录中没有明文设备号或 UID。Bootloader 流式扫描文件，只解开和自己 lookup 匹配的那一条。

## UPDATE.SEC

`UPDATE.SEC` 固定 188 字节：

- 格式魔数、版本、产品型号和 32 位 release。
- 授权记录数。
- App A/B 明文长度和 CRC32。
- App A/B 的 Nonce 和 GCM Tag。
- 完整 `DEVICES.SEC` 的 SHA-256。
- 覆盖上述所有字段的 64 字节 Ed25519 签名。

## Bootloader 拒绝条件

- 型号、格式或文件长度错误。
- Ed25519 签名错误。
- `DEVICES.SEC` 的 SHA-256 不匹配。
- 本机匿名 lookup 不存在、重复或信封 Tag 错误。
- App A/B 任意一个 GCM Tag、向量表或 CRC 错误。
- release 不高于本机已记录版本。

所有文件均验证通过以后，Bootloader 才会擦除非活动 App 分区。
